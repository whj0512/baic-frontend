# BAIC 后端部署说明

## 1. 文档说明

本文档适用于本交付包中的 BAIC 后端服务。后端基于 Python、FastAPI 和 Uvicorn，业务数据默认使用 SQLite；部分知识图谱接口依赖外部 GraphDB 服务。

下文假设已将交付目录复制到服务器，并将其记为 `<backend_dir>`。执行命令前请先进入该目录：

```text
cd <backend_dir>
```

> Windows 示例目录：`D:\BAIC\backend`  
> Linux 示例目录：`/opt/baic/backend`

## 2. 运行环境要求

- 操作系统：Windows 10/11、Windows Server 或主流 Linux 发行版。
- Python：建议使用 3.9～3.11 的 64 位版本。
- 网络：默认监听 `127.0.0.1:8765`；若需供其他主机访问，应改为 `0.0.0.0`，并配置防火墙或反向代理。
- 磁盘权限：运行服务的用户必须对 SQLite 数据库及其所在目录具有读写权限。
- GraphDB：只有使用 `/graphdb/*` 或将依赖关系持久化至图数据库时才需要。普通项目、需求、模型和测试用例接口可只使用 SQLite。

## 3. 交付包中的关键文件

| 文件或目录 | 说明 |
| --- | --- |
| `main.py` | FastAPI 应用入口 |
| `requirements.txt` | Python 依赖清单 |
| `DB/baic.sqlite3` | 随交付包提供的 SQLite 业务数据库 |
| `DB/sqlite_init.sql` | SQLite 全量建表脚本，会删除并重建现有表 |
| `DB/init_sqlite.py` | 执行 SQLite 全量建表脚本的辅助程序 |
| `DB/dbconfig.json` | SQLite 数据库路径配置文件 |
| `DB/graphdb_config.json` | GraphDB 连接及命名图配置 |
| `DB/graphdb_config.example.json` | GraphDB 配置示例 |
| `API_DOCUMENTATION.md` | HTTP/WebSocket 接口文档 |

## 4. 安装 Python 依赖

建议使用独立虚拟环境，避免与服务器上的其他 Python 项目互相影响。

### 4.1 Windows PowerShell

```powershell
cd D:\BAIC\backend
py -3.10 -m venv .venv
Set-ExecutionPolicy -Scope Process Bypass
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

若服务器只安装了一个 Python，也可将 `py -3.10` 改成 `python`。

### 4.2 Linux

以下命令以 Python 3.10 为例：

```bash
cd /opt/baic/backend
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

若安装依赖时提示编译工具或系统库缺失，请先通过操作系统的软件包管理器补充 Python 开发包、C/C++ 编译工具等，再重新执行安装命令。

## 5. 必须确认的数据库配置

### 5.1 当前实际使用 SQLite

当前版本的 `db_client.py` 只连接 SQLite，不会连接 MySQL。数据库路径的生效优先级为：

1. 环境变量 `BAIC_SQLITE_PATH`；
2. 未设置环境变量时，读取 `DB/dbconfig.json` 中的 `SQLITE_PATH`；
3. 环境变量及配置文件均未提供有效路径时，使用 `<backend_dir>/DB/baic.sqlite3`。

交付时的默认配置为：

```json
{
  "SQLITE_PATH": "DB/baic.sqlite3"
}
```

相对路径以 `<backend_dir>` 为基准，因此上述配置指向 `<backend_dir>/DB/baic.sqlite3`。也可以填写绝对路径，例如 Windows 的 `D:\\BAIC\\data\\baic.sqlite3` 或 Linux 的 `/var/lib/baic/baic.sqlite3`。JSON 中的 Windows 反斜杠必须写成双反斜杠。

推荐在生产环境中将数据库放在独立、可备份的数据目录中，并通过环境变量或配置文件填写绝对路径。环境变量优先级最高，设置后会覆盖配置文件。

Windows PowerShell：

```powershell
$env:BAIC_SQLITE_PATH = 'D:\BAIC\data\baic.sqlite3'
```

Linux：

```bash
export BAIC_SQLITE_PATH=/var/lib/baic/baic.sqlite3
```

请确保目标目录已经存在，且服务账户拥有读写权限。应用可以创建不存在的数据库文件，但不会自动执行完整的首次建表脚本。


### 5.2 新建空数据库

执行初始化脚本：

```text
python DB/init_sqlite.py
```

该脚本固定初始化 `<backend_dir>/DB/baic.sqlite3`，不会读取 `BAIC_SQLITE_PATH`。如需将新库放到其他位置，应先初始化，再复制生成的文件并设置 `BAIC_SQLITE_PATH`。

> 警告：`DB/sqlite_init.sql` 开头包含多个 `DROP TABLE IF EXISTS`。对已有数据库执行初始化会清除业务表及其中数据。初始化前必须备份，生产环境日常启动时不要执行此脚本。

### 5.3 数据库备份

停止后端服务后，可直接复制 SQLite 文件进行备份。例如：

Windows PowerShell：

```powershell
Copy-Item D:\BAIC\data\baic.sqlite3 D:\BAIC\backup\baic-20260812.sqlite3
```

Linux：

```bash
cp /var/lib/baic/baic.sqlite3 /var/backups/baic/baic-20260812.sqlite3
```

恢复时先停止服务，用备份文件替换正式数据库，然后重新启动。请勿在数据库有写入请求时直接覆盖文件。


## 6. GraphDB 配置（按需）

如需使用 GraphDB，先部署 GraphDB、创建仓库，然后修改 `DB/graphdb_config.json`：

```json
{
  "base_url": "http://127.0.0.1:7200",
  "repository": "baic",
  "repository_url": "",
  "username": "",
  "password": "",
  "auth_token": "",
  "timeout_seconds": 30,
  "verify_ssl": true,
  "retry": {
    "total": 3,
    "backoff_seconds": 0.4
  },
  "pool_connections": 10,
  "pool_maxsize": 20,
  "named_graphs": {
    "ontology": "urn:baic:graph:requirement-ontology",
    "instances": "urn:baic:graph:requirements:418",
    "legacy_dependencies": "urn:baic:graph:legacy-dependencies"
  },
  "files": {
    "ontology": "D:/BAIC/data/requirement-ontology.ttl",
    "instances": "D:/BAIC/data/requirements.ttl"
  },
  "application": {
    "connect_on_startup": true,
    "fail_startup": false,
    "startup_timeout_seconds": 5,
    "max_insert_triples": 1000
  }
}
```

需要重点修改：

- `base_url`：GraphDB 服务地址；
- `repository`：已创建的仓库名称；
- `username`、`password` 或 `auth_token`：启用认证时填写；
- `files.ontology`、`files.instances`：需要导入 RDF 文件时，改成服务器上的真实绝对路径；交付配置中的开发机路径不可直接使用；
- `application.fail_startup`：设为 `true` 时，GraphDB 连接失败会导致整个后端启动失败。

也可以通过环境变量覆盖敏感项，例如：

```bash
export GRAPHDB_BASE_URL=http://127.0.0.1:7200
export GRAPHDB_REPOSITORY=baic
export GRAPHDB_USERNAME=baic_user
export GRAPHDB_PASSWORD='请替换为实际密码'
```

若配置文件不放在默认位置，可设置：

```bash
export GRAPHDB_CONFIG_PATH=/etc/baic/graphdb_config.json
```

启动后端前可单独检查连接：

```text
python graphdb_client.py health
```

需要导入配置文件中指定的本体和实例数据时：

```text
python graphdb_client.py import
```

加 `--replace` 会替换配置中对应命名图的数据，执行前应确认并备份：

```text
python graphdb_client.py import --replace
```

## 7. 服务配置

建议至少设置以下环境变量：

| 变量 | 示例 | 说明 |
| --- | --- | --- |
| `BAIC_SQLITE_PATH` | `/var/lib/baic/baic.sqlite3` | SQLite 数据库绝对路径，生产环境建议显式设置 |
| `BAIC_HOST` | `0.0.0.0` | 直接运行 `main.py` 时的监听地址 |
| `BAIC_PORT` | `8765` | 直接运行 `main.py` 时的监听端口 |
| `BAIC_RELOAD` | `0` | 生产环境必须关闭热重载 |
| `AUTH_ENABLED` | `1` | 是否校验 Bearer Token；当前代码默认值为 `0` |
| `JWT_SECRET` | 随机长字符串 | JWT 签名密钥；启用认证时必须修改，不能使用代码默认值 |
| `JWT_EXP_DELTA_SECONDS` | `3600` | 本服务签发 JWT 的有效期，单位为秒 |


## 8. 启动流程

### 8.1 上线前检查

1. 进入后端目录并激活虚拟环境。
2. 确认依赖已成功安装。
3. 确认 `BAIC_SQLITE_PATH` 指向正确文件，且服务账户有读写权限。
4. 确认没有误执行全量初始化脚本。
5. 使用图数据库时，确认 `DB/graphdb_config.json` 中不再包含交付方开发机路径，并执行 GraphDB 健康检查。
6. 确认服务端口未被占用，防火墙及反向代理规则已配置。

### 8.2 开发或现场联调启动

Windows PowerShell：

```powershell
cd D:\BAIC\backend
.\.venv\Scripts\Activate.ps1
$env:BAIC_SQLITE_PATH = 'D:\BAIC\data\baic.sqlite3'
$env:AUTH_ENABLED = '0'
python -m uvicorn main:app --host 0.0.0.0 --port 8765 --reload
```

Linux：

```bash
cd /opt/baic/backend
source .venv/bin/activate
export BAIC_SQLITE_PATH=/var/lib/baic/baic.sqlite3
export AUTH_ENABLED=0
python -m uvicorn main:app --host 0.0.0.0 --port 8765 --reload
```

`--reload` 只用于开发或联调，不应在生产环境使用。

### 8.3 生产环境前台启动

```text
python -m uvicorn main:app --host 0.0.0.0 --port 8765 --workers 1
```

不要在生产环境直接执行 `python main.py`：该入口的 `BAIC_RELOAD` 默认值为 `1`，会开启热重载。若必须使用该入口，至少设置 `BAIC_RELOAD=0`。

### 8.4 Linux systemd 示例

创建 `/etc/baic/baic.env`，内容示例：

```ini
BAIC_SQLITE_PATH=/var/lib/baic/baic.sqlite3
AUTH_ENABLED=1
JWT_SECRET=请替换为随机长字符串
JWT_EXP_DELTA_SECONDS=3600
GRAPHDB_CONFIG_PATH=/etc/baic/graphdb_config.json
```

仅允许服务账户和管理员读取该文件。再创建 `/etc/systemd/system/baic-backend.service`：

```ini
[Unit]
Description=BAIC Backend API
After=network.target

[Service]
Type=simple
User=baic
Group=baic
WorkingDirectory=/opt/baic/backend
EnvironmentFile=/etc/baic/baic.env
ExecStart=/opt/baic/backend/.venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8765 --workers 1
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

加载并启动服务：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now baic-backend
sudo systemctl status baic-backend
```
