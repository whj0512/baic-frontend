# 页面设计说明

## 设计稿

[打开 1600 × 1000 PNG](./assets/ontology-ingestion-agent-page.png) · [打开可编辑 SVG](./assets/ontology-ingestion-agent-page.svg)

![多业务智能体任务工作台页面设计图，本体入库智能体为当前选中项](./assets/ontology-ingestion-agent-page.png)

设计目标是保留当前 Agent Workspace 的“项目侧栏 + 对话工作区”心智模型，同时把自由选择执行 Agent 的对话页升级为可切换多个业务智能体的受控任务工作台。设计稿展示“本体入库智能体”选中后的具体内容，不代表通用壳只能支持三阶段本体流程。

## 页面区域

| 区域 | 主要内容 | 交互目的 |
| --- | --- | --- |
| 左侧上下文区 | 当前项目、业务智能体选择、新建任务、当前智能体任务历史 | 用户以项目、业务智能体和任务为单位工作，不选择内部执行 Agent |
| 顶部身份区 | 当前业务智能体名称/描述、连接状态、项目工作区导航 | 身份内容由工作流定义驱动，保留原页面导航能力 |
| 工作流步骤条 | 当前定义声明的步骤；本体为文档条目化、单功能建模、本体关系管理 | 支持不同智能体拥有不同数量和名称的步骤 |
| 中央执行时间线 | 表单、用户确认、Agent 活动、结构化产物卡片 | 将多会话合并成一条可审计流程 |
| 右侧产物中心 | 三条流水线的稳定产物入口 | 即使时间线很长，用户也能快速回看结果 |
| 底部输入区 | 补充说明、上传附件、停止当前执行 | 保留必要的对话灵活性，但不替代阶段按钮 |

## 首屏状态

用户先在当前项目下选择业务智能体。新建任务后，中央区域根据所选定义显示引导表单而不是空对话。本体入库表单为：

- 源需求文档：DOCX / PDF，必填。
- 同版本 Markdown：MinerU 或等价工具产出，必填。
- 项目输出根目录：用于提示 Agent 的产物组织方式，必填。
- 项目名称、建模目标：必填。
- 额外约束：选填，例如命名空间、功能范围、术语表。
- 开始按钮旁显示当前业务智能体依赖的 QwenPaw Agent 可用性；本体定义显示 12 个。

表单提交后会生成固定任务标识，并将表单内容作为流水线一的首条结构化输入写入 QwenPaw 会话。

## 阶段交互

以下是本体入库定义的专用交互。后续两个智能体通过自身定义替换步骤、表单和产物，不改变页面壳。

### 阶段一：文档条目化

- 时间线实时显示入口 Agent 和两个执行 Agent 的活动。
- 成功后展示现有 `chunks` 产物卡片，并提取可选功能。
- 用户可多选功能，系统显示预计建模任务数。
- “确认并开始批量建模”是进入阶段二的唯一入口。

### 阶段二：单功能建模

- 顶部显示批次总进度，例如“3 / 5 已完成”。
- 每个功能为独立任务卡，含四个子步骤和独立状态。
- 首版逐个功能执行；失败项可以单独重试或移出本批次。
- 全部有效功能完成后，用户统一确认进入本体阶段。

### 阶段三：本体关系管理

- 第一段只生成、解析、推理和校验 TTL，不携带 GraphDB 写入授权。
- TTL 可查看后，页面显示独立授权表单：服务地址、仓库名、写入模式和确认勾选。
- 默认地址可预填为 `http://localhost:7200`，默认仓库可预填为 `requirement`，但用户必须主动确认。
- 写入成功后显示 GraphDB 结果、实例/关系概览和失败明细。

## 状态语义

| 状态 | 颜色 | 页面行为 |
| --- | --- | --- |
| 未开始 | 灰色 | 可查看前置条件，不能跳过 |
| 运行中 | 蓝色 | 显示流式活动，可停止当前任务 |
| 待确认 | 金色 | Agent 已停止执行，等待用户按钮 |
| 已完成 | 绿色 | 产物固定到右侧中心，可重新打开 |
| 部分失败 | 橙色 | 成功项保留，失败项允许重试或排除 |
| 失败 | 红色 | 显示可操作的错误、重试和原始诊断 |

“待 GraphDB 授权”必须使用“待确认”，不能用“失败”或“离线”表示。

## 视觉规范

- 桌面基准尺寸：1440 px 以上；设计稿按 1600 × 1000 输出。
- 左侧栏宽度：280 px；右侧产物中心宽度：300–340 px。
- 主色：`#2563EB`；成功：`#16A34A`；待确认：`#D97706`；错误：`#DC2626`。
- 背景使用冷灰，卡片使用白色和 1 px 边框，避免过度圆角和大面积渐变。
- 产物文件名、Agent ID、会话 ID 使用等宽字体；业务文案使用现有系统字体。
- 所有状态不能只依赖颜色，同时提供图标和文字。

## 响应式与无障碍

- 1200–1439 px：右侧产物中心变为可展开抽屉，步骤条保持横向。
- 低于 1200 px：左侧栏沿用现有抽屉行为，时间线保持单列。
- 阶段步骤、任务卡和产物卡都提供 `aria-current` / `aria-expanded` / `aria-live`。
- 键盘可以完成项目切换、功能多选、阶段确认、失败重试和产物打开。
- 流式更新仅更新局部 `aria-live="polite"` 区域，避免整页重复朗读。
- 业务智能体选择器使用可搜索列表，键盘切换时先提示存在的运行中任务，避免误中止当前 SSE。
