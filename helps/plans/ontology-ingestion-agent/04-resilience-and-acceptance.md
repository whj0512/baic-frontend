# 第四阶段：韧性、回归与交付

## 阶段目标

覆盖长任务、多会话、项目切换、业务智能体切换和外部服务失败，确保标准场景可完整执行，异常场景不会误跳步骤、丢失成功产物或覆盖其他项目/业务智能体状态。

## 中断与恢复

### 页面刷新

- 根据当前业务智能体定义重新加载其入口 Agent ChatSpec 并聚合 Run；本体定义加载三个入口 Agent。
- 打开 Run 后按需加载相关历史并重建 reducer。
- 若某个会话仍为 `running`，显示“远端可能仍在执行”，允许刷新历史，不擅自重发。
- 未提交表单草稿从 `sessionStorage` 恢复；已提交任务不依赖本地草稿。

### 项目切换

- 立即停止当前浏览器 SSE。
- 清除当前项目可见 Run 与附件状态。
- 所有异步回调校验 `projectId / runId / requestId`。
- 切回原项目时从远端历史恢复，不复用另一个项目的内存快照。

### 业务智能体切换

- 当前 Job 正在流式执行时先提示用户；确认切换后停止当前浏览器 SSE。
- 清除当前可见任务、附件和定义专用组件状态，但保留项目选择。
- 更新同路由的 `?agent={businessAgentId}`。
- 只加载新定义的 `entryAgentIds` 和该业务智能体历史。
- 切回原业务智能体时从远端恢复，不把另一智能体的步骤、产物或表单草稿带回。

### 用户停止

- 停止只作用于当前 Job。
- 已完成产物继续保留。
- 队列暂停，不自动启动下一个功能。
- 用户可继续当前会话或重试该 Job。

## 失败处理矩阵

| 场景 | 页面状态 | 恢复动作 |
| --- | --- | --- |
| QwenPaw 离线 | 全局离线，禁止新任务 | 重试连接与 Agent 列表 |
| 当前定义所需 Agent 缺失 / 禁用 | 该业务智能体启动检查失败 | 显示具体 ID，重新检查；其他业务智能体保持可用 |
| 某入口 ChatSpec 列表失败 | 历史不完整 | 单独重试该入口，不清空其他入口 |
| 文件上传失败 | 表单保留 | 重试单个附件 |
| HTTP 200 但 SSE 无事件 | 输入协议错误 / 等待超时 | 检查非空 TextContent，不创建重复 Run |
| SSE 中断且无终态 | 当前 Job 失败 / 未知 | 刷新历史或继续原会话 |
| ChatSpec 存在但历史为空 | 历史未落盘 / 已丢失 | 显示不可恢复状态，不误判完成 |
| 403 / 404 / 500 | Agent 禁用、不存在、Chat 不存在或服务异常 | 保留上下文，按状态码给出针对性重试 |
| 协议 JSON 无效 | 协议错误，不推进 | 展开原文，要求 Agent 重发 |
| 查询 Skill 只有路径或 payload 缺失 | 产物 `declared/unavailable`，不推进 | 继续原 Job 会话重新查询，不把路径渲染成链接 |
| fenced/tool payload 被截断 | 产物不可解析，不推进 | 使用 summary/filtered 查询重新获取 |
| 功能建模部分失败 | `partially_failed` | 单项重试或人工排除 |
| TTL 校验失败 | 本体阶段失败 | 修正后重试，不显示授权按钮 |
| 用户未授权 GraphDB | `awaiting_confirmation` | 修改目标或确认授权 |
| GraphDB 上传失败 | 写入失败，TTL 保留 | 检查地址 / 仓库后仅重试上传 |
| GraphDB 推理失败 | 部分完成 | 保留写入结果，单独重试推理 |

## 性能边界

- Agent 列表在页面生命周期内只加载一份。
- 当前业务智能体 `entryAgentIds` 的完整 ChatSpec 列表并行加载，按 `projectId + businessAgentId` 在内存中缓存短期结果；API 没有分页和前缀筛选，不能伪造服务端分页。
- 侧栏不加载历史消息，只聚合 ChatSpec。
- 打开 Run 时按需加载历史，详情请求并发上限为 2；使用受限 LRU，避免长期占用所有任务消息。
- ChatSpec 展示顺序完全由前端按 `updated_at` 计算，不依赖服务端存储顺序。
- 流式消息只更新当前 Job，其他功能卡使用摘要状态。
- 大型 chunks / DSL / TTL 原始数据延迟展开，默认只查询和渲染摘要；完整内容通过
  `query-project-chunks detail=full`、DSL v2 filtered 或本体产物 filtered 查询按需
  获取。
- `query-requirement-dsl-artifacts` v1 会返回完整 DSL，第零阶段必须记录标准项目
  payload 体积；超过预算时第三阶段 v2 完成前不得启用自动批量查询。
- 产物列表和功能列表达到约 100 项时启用窗口化或分页；首版至少避免一次渲染完整原始 JSON。

## 安全与数据边界

- 不在 `localStorage`、`sessionStorage`、URL、日志和协议消息中保存 GraphDB 密码。
- 远程 QwenPaw 的 Bearer Token 不进入 Vite 客户端构建或浏览器存储；由同源代理/反向代理在服务端注入。
- 文件 URL 和产物 URL 延续现有 QwenPaw 安全边界，不自行拼接本地文件协议。
- Markdown 链接继续使用 `target="_blank"` 和 `rel="noreferrer noopener"`。
- 所有 Agent 返回数据先做运行时结构校验，再进入状态机。
- 前端只提供写入授权 UX；真正的不可绕过授权需要后端支持。

## 人工回归矩阵

### 标准场景

1. 选择已有项目。
2. 选择“本体入库智能体”并新建任务。
3. 上传源文档和同版本 Markdown。
4. 完成条目化，确认自动出现 `query-project-chunks` summary 产物，并按需查询 full。
5. 多选至少三个功能。
6. 观察功能队列逐项完成，打开 DSL；在 v2 联调后继续打开上下文、对齐和测试用例。
7. 确认进入本体阶段，通过 `query-project-ontology-artifacts` 查看 TTL 和校验结果。
8. 在未授权状态刷新页面，确认仍停留在待确认。
9. 授权本地 GraphDB 追加写入。
10. 查看上传、推理产物，并通过 `query-project-ontology-instances` 打开最终关系图。
11. 离开再返回任务，确认所有阶段和产物可恢复。
12. 核对详情请求使用 `ChatSpec.id`，继续任务仍复用 `session_id / user_id / channel`。

### 多业务智能体扩展场景

1. 注册一个单步骤、无附件的测试 fixture。
2. 注册一个两步骤、带人工确认和自定义产物的测试 fixture。
3. 在本体与两个 fixture 之间切换，确认项目不变、任务历史分别隔离。
4. 分别新建 draft，确认表单草稿按 `projectId + businessAgentId` 隔离。
5. 让其中一个 fixture 的依赖 Agent 不可用，确认不阻断本体任务。
6. 刷新带 `?agent=` 的页面，确认恢复正确业务智能体；无效 ID 安全回退。
7. 卸载测试 fixture，确认生产构建只显示正式注册的业务智能体。

### 部分失败

- 第二个功能失败后，第三个功能是否按用户选择继续。
- 失败功能重试是否不影响成功功能。
- 排除失败功能是否留下审计记录。
- TTL 校验失败时是否隐藏 GraphDB 授权按钮。
- GraphDB 上传失败后是否保留 TTL 并只重试写入。

### 项目与旧功能回归

- 项目列表加载、创建、自动进入新项目。
- 删除当前项目后返回欢迎页。
- 侧栏抽屉、Esc 关闭和窄屏布局。
- `/workspace/:projectId?view=...` 导航。
- 原有消息 Markdown、附件、chunks、DSL 产物、本体实例面板。
- 旧独立 Agent ChatSpec 没有被删除或修改。
- 三个业务智能体的任务索引不会互相混入。
- ChatSpec 大量存在时，任务索引仍由客户端正确筛选和排序。
- 模拟 ChatSpec 存在但历史为空时，页面不把它显示为已完成。
- 模拟 SSE 中出现 content/plugin 局部完成事件时，页面等待 response 终态。

## 分阶段交付约束

每个实施阶段都应：

1. 只提交该阶段范围内的代码。
2. 给出变更文件清单和手工验证步骤。
3. 保留用户工作区内无关修改。
4. 等待用户人工确认后进入下一阶段。

根据仓库约定，本任务完成代码修改后不运行 `eslint` 和 `tsc --noEmit`，由 CI 负责。可执行补丁格式检查和针对性的页面手工验证。

## 最终验收条件

- 标准场景能够从文档走到 GraphDB 关系产物。
- 用户可随时查看三条流水线的完成产物。
- 刷新、项目切换和历史恢复不丢 Run 状态。
- 阶段推进只依赖结构化消息和用户确认。
- 部分失败可局部恢复，不要求整个任务重跑。
- GraphDB 未授权时不会由前端触发上传。
- 页面没有重新暴露 12 个独立 Agent 的选择入口。
- 页面提供业务智能体选择入口，但不暴露其内部 QwenPaw Agent 选择。
- 现有项目管理、对话基础能力和工作区导航无回归。
- 实现没有依赖 QwenPaw 文档未提供的 Session 创建、更新、删除、分页或批量历史接口。
- 两个测试 fixture 证明可以新增后续业务智能体而不修改 `AgentStore.tsx`、通用页面壳和通用 reducer。
