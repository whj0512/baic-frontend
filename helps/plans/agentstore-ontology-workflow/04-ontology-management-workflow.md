# 阶段四：场景 7、8、9 与本体实例查询

## 1. 阶段目标

在用户确认全部功能 DSL 后，依次接入：

1. 场景 7：只生成和校验本地 TTL；
2. 场景 8：获得明确写入授权后追加 ABox；
3. 场景 9：获得独立推理授权后分析依赖与冲突；
4. 调用现有 `query-project-ontology-instances` 展示当前项目关系图。

场景 7、8、9 没有与 chunks/DSL 相同的完整结构化产物协议，因此采用“固定提示词识别 + Assistant 生成结束 + 用户明确确认”推进。任何自然语言完成表述都不能替代用户确认。

## 2. 前置条件

- 用户已确认阶段三人工验收通过。
- 当前对话存在最新成功 DSL 面板。
- DSL `feature_count` 与当前 chunks 功能数一致。
- 用户已点击“确定全部功能 DSL 已审核”。

## 3. 场景 7：本地 TTL 校验

### 3.1 表单字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 项目根目录 | 是 | 默认使用流水线二项目根目录 |
| TTL 输出路径 | 是 | 用户指定的本地绝对路径 |
| 补充要求 | 否 | 不能覆盖只读边界 |

### 3.2 固定提示词

```text
请将该项目已验证的 DSL 和 requirement_relations.json 转换为 TTL。
项目根目录：<项目根目录>
输出 TTL：<TTL 输出路径>
只做本地 Turtle 校验，不连接、不上传、不修改 GraphDB。
请返回 TTL 路径、实体/关系统计、校验结果和问题列表。
补充要求：<用户内容，仅非空时添加>
```

固定的 GraphDB 禁止语句必须位于补充要求之前，用户补充文本不得删除或替换它。

### 3.3 推进规则

- 发送场景 7 后显示“等待本地 TTL 结果”。
- Assistant 停止生成后显示“TTL 与本地校验已确认”。
- 用户点击确认前不显示场景 8 表单。
- 点击确认只改变当前 UI，不发送消息、不连接 GraphDB。
- 若刷新发生在确认后而场景 8 尚未发送，用户需要重新确认。

## 4. 场景 8：GraphDB 上传

### 4.1 表单字段

| 字段 | 默认值 | 必填 |
| --- | --- | --- |
| TTL 路径 | 最近一次场景 7 的 TTL 输出路径 | 是 |
| GraphDB 地址 | `http://localhost:7200` | 是 |
| 仓库 | `requirement` | 是 |
| 写入授权 | 未勾选 | 是 |

授权控件文字固定为：

```text
我明确授权向上述 GraphDB 仓库追加本项目 ABox。
```

不得默认勾选，也不得因为用户曾确认场景 7 而自动授权。

### 4.2 固定提示词

```text
我明确授权向 GraphDB 写入本项目 ABox。
TTL：<TTL 路径>
GraphDB 地址：<GraphDB 地址>
仓库：<仓库>
仅追加该 ABox；不得清库、不得覆盖 TBox/SHACL、不得执行推理。
请返回上传状态、三元组数量、中文标签抽样和 SHACL 验证结果。
```

只有授权已勾选、必填字段完整、当前可发送且未生成时才启用发送。

### 4.3 推进规则

- 发送场景 8 后立即清除授权勾选，防止重复授权残留。
- Assistant 停止生成后显示“上传与 SHACL 结果已确认”。
- 用户点击确认前不显示场景 9 表单。
- 点击确认不自动执行推理。
- 切换对话、项目或新建会话时授权始终重置为未勾选。

## 5. 场景 9：关系推理

### 5.1 表单字段

| 字段 | 默认值 | 必填 |
| --- | --- | --- |
| 项目标识 | 当前项目名称；无名称时使用项目根目录 | 是 |
| GraphDB 地址 | 最近一次场景 8 地址 | 是 |
| 仓库 | 最近一次场景 8 仓库 | 是 |
| 推理授权 | 未勾选 | 是 |

授权文字固定为：

```text
我明确授权在上述 GraphDB 仓库执行本体关系推理。
```

场景 8 的写入授权不能复用为场景 9 推理授权。

### 5.2 固定提示词

```text
我明确授权在 GraphDB 仓库 <仓库> 上执行本体关系推理。
GraphDB 地址：<GraphDB 地址>
项目：<项目名称或根目录>
请推理并导出数据依赖、写冲突、状态机问题和关系证据。
每条推理关系必须包含 relationSource、relationTarget、isInferred=true、subtype 和 evidence；
不要把同名信号、共享连接或目录层级单独判定为依赖。
```

发送后立即清除推理授权勾选。

### 5.3 推进规则

- 场景 9 消息发送后显示“等待推理结果”。
- Assistant 停止生成后开放“查看本体实例关系”。
- 不把自然语言结果自动转换为结构化关系或写入前端状态。

## 6. 查询本体实例

按钮发送：

```text
请使用 $query-project-ontology-instances 加载当前项目的本体实例关系图。
```

实现规则：

- 使用现有 `onSend`，不直接调用 GraphDB API。
- 只检查最新场景 9 消息之后的 ontology tool panel。
- 复用 `extractToolPanels` 与现有 ontology handler。
- `payload.state === "ready"` 时标记本轮流程 completed。
- `loading` 保持等待；`parse-error` 保持场景 9 active 并允许重试。
- 关系卡片继续从 `activeConversation.projectId` 获取当前项目，不向 Skill 提示词添加前端项目 ID。

## 7. 历史恢复

按固定首行识别场景消息：

- 场景 7：`请将该项目已验证的 DSL 和 requirement_relations.json 转换为 TTL。`
- 场景 8：`我明确授权向 GraphDB 写入本项目 ABox。`
- 场景 9：`我明确授权在 GraphDB 仓库`

恢复规则：

- 存在场景 8 消息即证明用户曾在发送时完成场景 7 确认，可恢复到场景 8 已发起状态。
- 存在场景 9 消息即证明用户曾完成场景 8 确认，可恢复到场景 9 已发起状态。
- 没有下一场景消息时，本地确认不持久化，刷新后要求重新确认。
- 最新 ontology panel ready 时恢复为流程完成。
- 不解析任意自然语言中的“上传完成”“推理完成”作为阶段标记。

## 8. 防重复与错误状态

- `streaming=true` 时禁用所有场景发送、确认和 Skill 查询按钮，只保留现有停止生成能力。
- 请求失败时保留表单内容，但授权勾选保持清除，重试写入或推理前必须重新授权。
- Skill 解析失败时展示现有错误面板和工作流重试入口，不隐藏原始消息。
- 切换项目或对话时，未发送的路径、仓库和授权草稿不得泄漏到新上下文。

## 9. 本阶段不得实施

- 不自动执行 GraphDB 上传或推理。
- 不将 GraphDB 授权默认勾选或跨场景继承。
- 不新增查询 TTL、上传报告或推理报告的假协议。
- 不修改 ontology marker、GraphDB API 或 ReqRelationShip 数据加载逻辑。
- 不用 `ChatSpec.status` 或 assistant 普通文字替代用户确认。

## 10. 阶段交付与停止

完成代码修改后：

1. 只检查本次改动范围和差异。
2. 不运行自动构建、测试或浏览器自动化。
3. 提交阶段报告，引用 E 组、G05-G08、H04-H06。
4. 明确停止，等待用户完成最终人工验收。
5. 用户未确认清单全部项目时，不宣布整体完成。
